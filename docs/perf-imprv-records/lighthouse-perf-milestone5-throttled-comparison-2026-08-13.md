# 里程碑 5：4x CPU 节流发布级对比（2026-08-13）

> 分支：`feat/lighthouse-perf-optimization`。
> 前序：M4（无障碍与 SEO 清零）。
> 性质：**纯测量里程碑**——无任何源码改动，交付为基线报告回填与本记录。
> 级别：L1（测量 + 文档，低风险局部修改，plan 可选）。

## 1. 背景与目标

M1–M3b 的所有性能数字均在无节流 localhost 实验室环境测得。基线报告与 M2 记录
明确约定"节流下的严格对比留待里程碑 5 统一执行"，并预测"4x CPU 节流下相对收益
预计放大 3–4 倍"。本里程碑兑现该承诺：

1. **节流 A/B**：基线提交（153fb11）与 HEAD 生产产物，同协议 4x 节流各测 3 轮；
2. **挂载任务修复复测**（M3b §6.2 后测仅 1 轮的欠账）；
3. **rAF 循环节流复核**（M3b §6.3 顺带项，预测 4x 下约 3.6ms/帧）；
4. **导航交互延迟**（INP 实验室代理；也是 M3b 建议 3 导航预取的验证前提）；
5. **冷会话地板回填**基线报告。

## 2. 测量环境与协议

- 构建：基线 = `git worktree add --detach 153fb11` 于会话临时目录，依赖经
  `node_modules` 符号链接复用（基线与 HEAD 的 package.json/package-lock.json
  diff 为空，依赖逐字节一致，无需重装）；两构建产物分别由 `vite preview`
  服务于 :4174（基线）/ :4173（HEAD），同一 Chrome、同一会话内测量。
- 浏览器：Chrome DevTools MCP，视口 1280×800@2x（与 M3b 会话 dpr 一致，保证
  rAF 成本可比），**4x CPU 节流**，无网络节流。
- 预热：正式 trace 前先做一次丢弃式加载，吸收浏览器会话级一次性冷成本
  （冷成本另行在隔离上下文单独测）。
- 每轮：`performance_start_trace(reload, autoStop)` 采集原始 trace；
  事件级分析复用 M3 会话脚本（挂载任务归因、FCP 后 rAF 探针），另写
  nav→LCP 窗口"真实工作 vs 空壳任务"分类探针。
- 交互延迟：注入 `PerformanceObserver('event')`（EventTiming，INP 官方口径）
  + MutationObserver（路由内容挂载时刻），MCP 真实输入事件点击。

## 3. 结果

### 3.1 首页加载（4x 节流，暖态，3 轮）

| 指标 | 基线（153fb11） | HEAD | 变化 |
| --- | --- | --- | --- |
| LCP 中位数 | 634 ms（595–1062） | 361 ms（351–373） | **−43%** |
| 最长挂载任务 | 412.0 ms（408.5–818.9） | 186.1 ms（170.5–199.9） | **−55%** |
| FCP 前主线程繁忙 | 569.5 ms（548.8–1035.6） | 373.5 ms（337.3–375.2） | **−34%** |
| CLS | 0.00 | 0.00 | 无回归 |

HEAD 三轮极其稳定（351–373ms，带宽 22ms）；基线方差大（595–1062ms）。基线
run1（1062ms LCP / 818.9ms 任务，内含 506ms Layout）为异常值，形态与 M3b
问题 3 记录的首 trace 采集竞争伪影一致，且可能叠加了残余冷字体成本；
中位数口径不受其影响。

**节流放大预测验证**（基线报告："预计放大 3–4 倍"）：
- 百分比口径：无节流 −17% → 节流 −43% = 放大 **2.5 倍**；
- 绝对差值口径：65 ms → 273 ms = 放大 **4.2 倍**。
两种口径下预测均成立（2.5–4.2x），基线报告的"3–4 倍"落在区间内。

### 3.2 帖子详情加载（4x 节流，暖态，3 轮）

| 指标 | 基线 | HEAD | 变化 |
| --- | --- | --- | --- |
| LCP 中位数 | 677 ms（659–688） | 670 ms（653–690） | −1%（噪声内） |
| CLS | 0.00 | 0.00 | — |

无差异。nav→LCP 窗口由真实主线程工作主导（数百 ms 布局/样式树/微任务，两构建
同构）；hljs 77KB 瘦身在 localhost 无传输成本的实验室环境不可测——M2 的诚实
结论在节流下复现。M2 的可度量收益（真实网络传输与解析削减）仍按 M2 记录预期
兑现，本里程碑未提供新证据。

### 3.3 挂载任务修复复测（M3b §6.2 欠账）

| 挂载任务构成 @4x | 基线 | HEAD |
| --- | --- | --- |
| 任务内 Layout | 97–115 ms | 64.9–74.1 ms |
| 任务内 UpdateLayoutTree | 116–118 ms | 20.7–37.8 ms |
| 任务内微任务 | 145–383 ms | 70.9–165.9 ms |

×4 标度一致性验证：HEAD 挂载任务内 Layout 64.9–74.1ms ≈ M3b 后测 17.05ms ×4
（68.2ms）✓；基线 97–115ms ≈ 24–29ms ×4，对应"全页静态挂载 + 强制回流双布局"
的无节流形态。M3b 的 −11.5ms 无节流挂载任务收益在节流下按 ×4 标度保持
（预期 ~−46ms，实际体现在基线 vs HEAD 的 186–412ms 差距中，与 M1 懒加载
贡献叠加）。修复机制（无 canvas 强制读、首帧绘制移出挂载任务）在节流下无
回归。

### 3.4 rAF 循环节流复核（M3b §6.3 顺带项）

| 指标 @4x | 基线 | HEAD |
| --- | --- | --- |
| 光束动画每帧主线程成本 | ~3.7–4.0 ms（列车样本） | **3.2–3.5 ms** |
| FCP 后 3s 窗口 3–5ms 帧任务数 | 178–180 | 165–180 |
| 窗口内最大任务 | 6.1–10.9 ms | 5.9–8.4 ms |

M3b 预测值 3.56ms/帧（0.89×4）被实测命中。每帧成本远低于 16.7ms 帧预算，
对 INP 的贡献上限 ≈3.5ms；重栅格化仍在合成器/栅格线程（M3 结论）。**复核
通过，维持 M3b"不动动画、无需改动"的判决。** 基线同量级说明光束动画循环
本身从未被优化改动，两侧数据互证。

### 3.5 导航交互延迟（INP 实验室代理，4x 节流）

| 交互 | 构建 | EventTiming click duration | 路由内容挂载（点击→DOM） | input delay |
| --- | --- | --- | --- | --- |
| 首页→论坛 | HEAD | 64 / 64 / 64 ms | 60 / 66 ms | 3–18 ms |
| 首页→论坛 | 基线 | 80 / 64 / 64 ms | 76 / 63 / 83 ms | 5–6 ms |
| 日历「上个月」 | HEAD | 64 / 64 ms | —（就地重渲染） | 2–5 ms |

全部远低于 200ms「良好」阈值（4x 节流下）。HEAD 导航略优（~12ms，噪声边缘）。
**边界（诚实声明）**：localhost 下路由 chunk 获取近乎零成本，真实网络下
chunk 传输会显著放大导航延迟——M3b 建议 3（hover 预取）的真实收益本地不可测，
保持开放；本测量只证明"渲染侧交互路径"健康。

### 3.6 冷会话地板（隔离浏览器上下文，冷缓存首载，4x 节流）

| 指标 | 冷载（HEAD） | 暖态（HEAD 中位） |
| --- | --- | --- |
| FCP | 1104 ms | ~360 ms |
| LCP | 1103 ms | 361 ms |
| Render delay | 1079 ms | ~357 ms |
| CLS | 0.00 | 0.00 |

冷载 ForcedReflow 洞察总量 610ms，归因于 Vue 运行时挂载路径
（`Xc @ vendor-vue-*.js`），≈ 无节流 150ms，与 M3 实验的冷字体地板
（118ms 无节流）同量级。**M3 判决在节流下重现**：浏览器会话级一次性
CJK 字体塑造成本以 ~4x 放大，应用层不可消除，仅影响会话内首次访问。

## 4. 遇到的问题与解决

### 问题 1：基线构建的环境复用

临时 worktree 不共享 node_modules。因 package-lock 逐字节一致（已验证），
符号链接复用主仓库依赖，两构建用完全相同的工具链与依赖字节，A/B 可比性
有保证；避免了 `npm ci` 的分钟级开销与锁文件漂移风险。

### 问题 2：autoStop 在空页截停 trace

冷载测量第一次尝试 `start_trace(reload=false, autoStop=true)` 于 about:blank，
trace 在导航前的空闲期就被截停（5s 空白产物，已删除）。改
`autoStop=false` + 手动导航 + `performance_stop_trace`，成功捕获冷导航。

### 问题 3：EventTiming duration 低估路由渲染延迟

EventTiming 的 duration 止于"事件处理后下一帧绘制"，若路由渲染尚未完成，
下一帧仍是旧内容，duration 会低估真实导航延迟。首轮测量暴露此问题后，
注入 MutationObserver（论坛页 h1 标记）与 rAF 帧计数，得到"点击→路由内容
挂载"完整延迟：HEAD 60/66ms、基线 76/63/83ms。EventTiming（64–80ms）与
挂载延迟（60–83ms）互为印证，结论一致。

### 问题 4：帖子页 ~660ms"空壳长任务"的再验证

帖子页 trace 的最长任务（~660–740ms）在挂载任务归因脚本下呈现"直接子事件
仅 ~6ms"的空壳形态——与 M3b 问题 3 的采集伪影模式相似。写分类探针下钻：
该任务外层是重复的嵌套 RunTask 壳，**内层嵌套壳下确有 ~580ms 真实工作**
（布局/样式树/微任务）。定性反转：是真实主线程工作，非伪影。教训：
"空壳"判定必须检查嵌套 RunTask 的内层，M3b 问题 3 的伪影判定仍成立
（该案例内层也确为空），但形态相似不能直接外推。

### 问题 5：测量脚本自身的控制台告警

交互测量后控制台出现 1 条 `Deprecated API for given entry type` warning。
无插桩重载后控制台复零——系测量脚本（PerformanceObserver event 类型注册）
触发，非应用代码。已记录，不影响结论。

### 问题 6：基线 run1 的 818.9ms 任务与 506ms Layout

基线首轮 trace 出现 2 倍于后两轮的挂载任务（内含 506ms Layout）。预热加载
已吸收会话冷成本，故归因为首 trace 采集竞争（M3b 问题 3 伪影类）叠加可能
的残余冷字体成本。处理：报告以中位数为主、注明范围与异常值形态，不
据此下结论。

## 5. 最终结论

1. **首页节流对比达成**：LCP 中位数 −43%（634→361ms）、最长挂载任务 −55%
   （412→186ms）、FCP 前繁忙 −34%（570→374ms）；"节流放大 3–4 倍"预测以
   2.5–4.2x（视口径）验证成立。
2. **帖子详情无差异**（677 vs 670ms）：M2 收益在 localhost 不可测的结论在
   节流下复现，非回归。
3. **M3b 两项欠账结清**：挂载任务修复在 4x 下按 ×4 标度保持；rAF 每帧
   3.2–3.5ms 命中预测值，维持"无需改动"判决。
4. **导航交互健康**：路由导航与日历交互在 4x 下 60–83ms，远低于 200ms
   阈值；渲染侧无 INP 风险，网络侧（chunk 传输）收益留待真实环境。
5. **冷会话地板文档化**：冷缓存首载 FCP/LCP ~1100ms @4x（暖态 ~360ms）；
   浏览器会话级冷字体成本（M3 的 118ms 无节流）以 ~4x 放大重现，应用层
   不可消除。
6. **验证**：CLS 全部 0.00；应用控制台零消息；`npm run check` 通过
   （见交付证据）。

## 6. 边界与后续

- 4x 节流 + localhost 仍是实验室数据：无网络节流，传输成本未模拟；
  仅用于相对对比与 INP 渲染侧验证。
- ForcedReflow 洞察在 4x 下两构建均出现（暖载窗口小，冷载 610ms 归因
  Vue 挂载路径）——M3b 无节流后测该洞察消失为实证，节流下重现属节流
  启发式差异 + 冷字体地板，非 M3b 回归；应用层无几何读取（全仓 rg
  证实），无新动作项。
- M3b 建议 3（导航预取）：本里程碑测得渲染侧延迟健康，预取收益取决于
  真实网络 chunk 传输，仍开放。
- 基线工作区与临时 worktree 为本次测量产物，留存于会话目录，不入库。
